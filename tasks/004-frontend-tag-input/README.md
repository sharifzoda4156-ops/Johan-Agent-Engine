# Тест № 004 — фронтенд: компонент ввода тегов

**Тип:** фронтенд (DOM, без фреймворка), новый проект с нуля. **Размер:** малый.

## Цель

Переиспользуемый компонент поля тегов на чистом JavaScript. Проверяем работу с DOM, событиями клавиатуры, доступностью и очисткой ресурсов.

**Стек:** Node.js 22+, ES-модули (`"type": "module"`), npm. Тесты — `node:test` + `jsdom` (единственная dev-зависимость). Без фреймворков, сборщиков и CSS-библиотек.

## Интерфейс

Файл `src/tagInput.js`, именованный экспорт:

```js
createTagInput(container, options) // → { getTags(), setTags(tags), destroy() }
```

`options` (все необязательны):

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| `initial` | `[]` | начальные теги |
| `maxTags` | `10` | максимум тегов |
| `onChange` | — | `onChange(tags)` после каждого изменения **действием пользователя** |
| `removeLabel` | ``tag => `Remove ${tag}` `` | текст `aria-label` кнопки удаления |

Компонент обязан работать с документом контейнера (`container.ownerDocument`), а не с глобальным `document`/`window`: тесты создают отдельный `JSDOM` на каждый случай.

## Разметка

Компонент добавляет в `container`:

```html
<ul class="tags">
  <li class="tag" data-tag="js">js<button type="button" class="tag-remove" aria-label="Remove js">×</button></li>
</ul>
<input class="tag-input" type="text" aria-label="Tags">
```

Текст тега вставляется как текст, не как HTML.

## Правила тега

Значение нормализуется: `trim()`, затем `toLowerCase()`. Допустимый тег — 1–30 символов из `a-z`, `0-9`, `-`, `а-я`, `ё`. Повторы (после нормализации) не добавляются.

## Поведение

- **Enter** или **`,`** (keydown): нормализовать значение поля. Пусто — ничего. Допустим и не повтор — добавить тег, очистить поле, снять `aria-invalid`. Повтор — очистить поле, тег не добавлять. Недопустим — оставить текст, поставить `aria-invalid="true"`. Для Enter и `,` вызывать `preventDefault()`.
- Событие **`input`**: если значение содержит запятые, части до последней запятой обрабатываются по очереди как выше (недопустимые и повторы молча отбрасываются), остаток после последней запятой остаётся в поле. Так работает вставка `a, b,c`: добавляются `a`, `b`, в поле остаётся `c`.
- **Backspace** при пустом поле удаляет последний тег.
- **blur**: непустое допустимое значение добавляется как при Enter; недопустимое остаётся с `aria-invalid="true"`.
- Клик по `.tag-remove` удаляет свой тег и возвращает фокус в поле.
- Когда тегов `maxTags`, поле получает `disabled`; после удаления снова доступно. Лишние теги не добавляются ни одним способом.
- Любой ввод пользователя, изменивший набор тегов, вызывает `onChange` с **копией** массива (изменение копии не влияет на компонент). Ввод без изменения набора `onChange` не вызывает.

## API

- `getTags()` — копия текущего массива в порядке добавления.
- `setTags(tags)` — заменить набор, `onChange` не вызывается. Каждый тег нормализуется; недопустимый тег или больше `maxTags` (после удаления повторов) → `TypeError`, состояние не меняется. То же для `initial` при создании.
- `destroy()` — удалить разметку компонента из контейнера и все обработчики; после этого события на старых узлах ни на что не влияют. Повторный вызов безопасен.
