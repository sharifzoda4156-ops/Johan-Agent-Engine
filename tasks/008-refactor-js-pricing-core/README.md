# Тест № 008 — многофайловый рефакторинг: единое ядро расчёта цен (Node.js)

**Тип:** бэкенд, рефакторинг нескольких модулей с сохранением API и новой фичей поверх. **Размер:** средний.

## Цель

В папке `starter/` лежит модуль цен интернет-магазина с тремя точками входа: `cartTotals` (витрина), `buildInvoice` (бухгалтерия) и `quote` (B2B). Каждая считает по-своему: свои таблицы налогов и промокодов, своё округление, свои ошибки. Один и тот же заказ даёт три разных итога. Нужно вынести расчёт в одно ядро, привести все три точки входа к правилам ниже и уже после этого добавить промокод `WELCOME5`. Проверяем, умеет ли агент делать рефакторинг по нескольким файлам, не ломая публичные API.

**Стек:** Node.js 22+, ES-модули, `node:test`, без зависимостей. Скопируй содержимое `starter/` в корень рабочего репозитория и работай там.

## Публичный API (форма не меняется)

- `cartTotals({ region, coupon, lines: [{ sku, price, qty }] })` — `price` число в основных единицах (`19.99`); возвращает `{ subtotal, discount, tax, total }` числами (`30.33`).
- `buildInvoice({ country, discountCode, items: [{ sku, unitPrice, quantity }] })` — `unitPrice` строка (`"19.99"`, `"7.5"`); возвращает `{ currency, lines: [{ sku, qty, unitPrice, amount }], subtotal, discount, tax, total }`, суммы строками с двумя знаками (`"30.33"`), `unitPrice` в строках счёта — как во входе.
- `quote(items, { region, code })`, `items: [{ sku, priceCents, qty }]`; возвращает `{ subtotalCents, discountCents, taxCents, totalCents }` целыми.
- Любая ошибка — `PricingError` из `src/errors.js` с полем `code`.

## Правила расчёта (одинаковы для всех трёх)

- Регионы: `us` — 0 %, USD; `de` — 19 %, EUR; `fr` — 20 %, EUR; `gb` — 20 %, GBP. Иначе `UNKNOWN_REGION`.
- Промокоды сравниваются без учёта регистра и пробелов по краям; пустой, пробельный, `null` или отсутствующий — скидки нет. `SPRING10` — 10 %; `VIP25` — 25 % при подытоге от 100.00; **новый** `WELCOME5` — минус 5.00 при подытоге от 30.00. Неизвестный код — `UNKNOWN_CODE`, подытог ниже порога — `MIN_SUBTOTAL_NOT_MET`.
- Позиция: цена ≥ 0, не больше двух знаков после точки; количество — целое от 1 до 1000. Иначе `INVALID_ITEM`. Пустой заказ допустим, всё по нулям.
- Арифметика в целых центах без потерь: подытог = Σ цена × количество; процентная скидка = подытог × % с округлением половины вверх до цента; фиксированная скидка не больше подытога; налог = (подытог − скидка) × ставка с округлением половины вверх, один раз на заказ; итог = подытог − скидка + налог.

## Известные расхождения (примеры, не полный список)

1. Заказ 10.50 × 3 в Германию: витрина считает итог 37.49, счёт 37.48, B2B-предложение 37.80 (верно 37.49).
2. `SPRING10` работает на витрине, а счёт его молча игнорирует.
3. В B2B-предложении налог Германии 20 % вместо 19 %.
4. Счёт для `gb` и `us` выставляется в EUR; для неизвестной страны счёт строится без налога вместо ошибки.
5. Витрина и счёт бросают обычный `Error` или молчат там, где B2B бросает `PricingError`.

## Требования к коду

- Таблицы регионов и промокодов, правила округления и расчёт существуют в одном месте; три модуля — тонкие адаптеры своего формата ввода и вывода. Имя каждого промокода и код валюты встречаются ровно в одном файле в `src/`.
- Экспорты модулей и форма ответов не меняются. Новые зависимости запрещены.

## Приёмка

Скрытые тесты прогоняют один и тот же заказ через все три точки входа и сравнивают с правилами выше, проверяют ошибки и единый источник правил. Существующие тесты в `test/` должны остаться зелёными; добавь тесты на ядро и на согласованность трёх точек входа. Команда: `npm test`.
