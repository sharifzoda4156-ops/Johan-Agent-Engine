# Тест № 006 — багфикс в чужом коде: курсорная пагинация (Node.js)

**Тип:** бэкенд, исправление ошибок в существующем коде. **Размер:** малый.

## Цель

В папке `starter/` лежит небольшой сервис ленты: функция `paginate` и HTTP-обработчик `GET /items`. Тесты зелёные, но клиенты жалуются. Нужно найти причины, исправить и закрыть регрессии тестами.

**Стек:** Node.js 22+, ES-модули, `node:test`, без зависимостей. Скопируй содержимое `starter/` в корень рабочего репозитория и работай там.

## Контракт (не менять)

- Порядок ленты: `createdAt` по убыванию, при равенстве `id` по убыванию (сравнение строк). `createdAt` — ISO-строка UTC одного формата, сравнивается как строка.
- `paginate(items, { limit, cursor })` → `{ items, nextCursor }`. Проход по всем страницам с `limit=N` выдаёт каждый элемент ровно один раз в порядке ленты. `nextCursor` равен `null` тогда и только тогда, когда после этой страницы элементов нет.
- Курсор непрозрачен для клиента; его формат можно менять. Исходный массив `items` не изменяется.
- `limit`: по умолчанию 20, целое от 1 до 100. В `GET /items` параметр приходит строкой из десятичных цифр.
- Ошибки HTTP: `400 {"error":{"code":"INVALID_LIMIT",...}}` и `400 {"error":{"code":"INVALID_CURSOR",...}}`. Используй уже объявленные `InvalidLimitError` и `InvalidCursorError`. Экспорты модулей и формат ответа `200` не меняются.

## Баг-репорты

1. «У нас много записей с одинаковым `createdAt` (пакетный импорт). Листаю по 2, и часть записей пропадает».
2. «На последней странице приходит `nextCursor`, а по нему пустая страница. Бывает, когда записей ровно кратно `limit`».
3. «`?limit=500` возвращает 500 записей, `?limit=abc` и `?limit=0` молча отдают 20». Ожидаем `400 INVALID_LIMIT` для всего, что не целое 1–100 (включая `1.5`, `-1`, `10abc`, пустую строку).
4. «Битый `cursor` (обрезанный при копировании) даёт `500`». Любой курсор, который сервис не выдавал бы, должен давать `400 INVALID_CURSOR`, а не `500` и не случайную страницу.
5. «После вызова `paginate` наш массив `items` оказался пересортирован».

## Приёмка

Скрытые тесты проверяют контракт и все пять репортов (через функцию и через HTTP). Существующие тесты в `test/` остаются зелёными; добавь регрессионный тест на каждый репорт. Команда: `npm test`.
