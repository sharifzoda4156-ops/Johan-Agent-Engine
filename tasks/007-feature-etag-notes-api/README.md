# Тест № 007 — фича в чужом коде: ETag и оптимистичные блокировки

**Тип:** бэкенд, доработка существующего сервиса. **Размер:** средний.

## Цель

В `starter/` лежит HTTP API заметок (Node.js, `node:http`, хранение в памяти) с тестами. Два клиента одновременно правят одну заметку, и последний молча затирает чужие правки. Нужно добавить версии, `ETag` и условные запросы по HTTP (RFC 9110). Проверяем, как агент встраивает фичу в чужой код, не ломая существующий контракт.

**Стек:** Node.js 22+, ES-модули, `node:test`, без зависимостей. Скопируй содержимое `starter/` в корень рабочего репозитория и работай там. Экспорт `createApp(store?)` из `src/app.js` сохраняется.

## Версии и ETag

- У заметки появляется поле `version` (целое). Новая заметка — `1`; каждый успешный `PUT` увеличивает на 1.
- `ETag` — сильный тег вида `"<version>"`, например `"3"` (кавычки входят в значение заголовка).
- Ответы `POST /notes` (201), `GET /notes/:id` (200), `PUT /notes/:id` (200) содержат заголовок `ETag` текущей версии.

## Условные запросы

**`GET /notes/:id` + `If-None-Match`:** значение — `*` или список тегов через запятую (пробелы вокруг допускаются; слабые `W/"3"` сравниваются слабо, то есть совпадают с `"3"`). Совпадение → `304` с пустым телом и заголовком `ETag`. Иначе обычный `200`.

**`PUT /notes/:id` и `DELETE /notes/:id` требуют `If-Match`:**

| Ситуация | Ответ |
| --- | --- |
| заметки нет | `404 NOT_FOUND` (независимо от `If-Match`) |
| нет заголовка `If-Match` | `428 PRECONDITION_REQUIRED` |
| `If-Match` не совпадает с текущим тегом | `412 PRECONDITION_FAILED`, заголовок `ETag` с текущей версией |
| совпадает | `PUT` → `200` с новой версией; `DELETE` → `204` |

`If-Match` — `*` (любая существующая заметка) или список тегов через запятую. Сравнение **сильное**: слабый тег `W/"3"` в `If-Match` не совпадает никогда. Порядок проверок строго по таблице, **до** валидации тела: при `412`/`428` тело не проверяется. Невалидное тело при совпавшем `If-Match` → `400 VALIDATION_ERROR`, версия не меняется.

Формат ошибок прежний: `{"error":{"code":"...","message":"..."}}`. Остальные маршруты и правила валидации не меняются.

## Приёмка

Скрытые тесты поднимают `createApp()` на случайном порту и проверяют всё выше, включая сценарий «два клиента правят одну заметку». Существующие тесты обнови под новый контракт (без `If-Match` `PUT`/`DELETE` теперь `428`), добавь свои. Команда: `npm test`. В README кратко описать протокол с примерами `curl`.
