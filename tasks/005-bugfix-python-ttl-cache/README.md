# Тест № 005 — багфикс в чужом коде: TTL-кэш на Python

**Тип:** Python, исправление ошибок в существующем коде. **Размер:** малый.

## Цель

В папке `starter/` лежит небольшая библиотека `ttlcache` (LRU-кэш с временем жизни записей) и её тесты. Тесты зелёные, но пользователи прислали баг-репорты. Нужно найти причины, исправить и закрыть регрессии тестами. Проверяем, умеет ли агент чинить чужой код, не ломая его контракт.

**Стек:** Python 3.11+, только стандартная библиотека, `unittest`. Скопируй содержимое `starter/` в корень рабочего репозитория и работай там.

## Контракт (не менять)

- `TTLCache(maxsize, ttl, clock=time.monotonic)`; `get(key, default=None)`, `set(key, value, ttl=None)`, `delete(key) -> bool`, `purge() -> int`, `key in cache`, `len(cache)`, счётчики `hits` и `misses`.
- Запись, созданная в момент `t` со сроком `ttl`, жива при `clock() < t + ttl` и просрочена при `clock() >= t + ttl`.
- Кэш — LRU: при переполнении вытесняется запись, к которой дольше всего не обращались. Обращение — это успешный `get` или `set` существующего ключа. `in` и `len` обращением не считаются и не меняют `hits`/`misses`.
- Просроченные записи не видны ни через `get`, ни через `in`, ни через `len`.
- Сигнатуры, имена и поведение, не упомянутые в баг-репортах, не меняются. Новые зависимости запрещены.

## Баг-репорты

1. «Ставлю `ttl=10`, читаю ровно через 10 секунд по своим часам и всё ещё получаю значение».
2. «Кэш на 2 элемента: положил `a`, `b`, прочитал `a`, положил `c`. Пропал `a`, хотя я только что его читал».
3. «Кэш заполнен. Обновил значение уже существующего ключа, и из кэша пропал другой ключ».
4. «`len(cache)` показывает 3, хотя все записи давно протухли, и `'a' in cache` возвращает `True` для протухшего ключа».
5. «`cache.set('a', 1, ttl=0)` молча принимается, а `TTLCache(..., ttl=0)` падает. Хочу одинаковое поведение»: `ttl <= 0` в `set` → `ValueError`, кэш не меняется.

## Приёмка

Скрытые тесты проверяют контракт выше и все пять репортов. Существующие тесты в `tests/` должны остаться зелёными; добавь регрессионный тест на каждый репорт. Команда: `python -m unittest`.
