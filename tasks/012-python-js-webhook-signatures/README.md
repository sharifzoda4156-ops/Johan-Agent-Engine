# Тест № 012 — Python + Node.js: подписи вебхуков, совместимые между языками

**Тип:** две кодовые базы на разных языках с общим протоколом; багфикс и доработка. **Размер:** средний.

## Цель

В папке `starter/` две реализации подписи вебхуков: `python/webhooks/` (основной отправитель) и `js/webhooks.js` (получатель, иногда тоже отправитель). Каждая проходит свои тесты, но вместе не работают: Node.js отклоняет почти все вебхуки от Python, а Python не может проверить подписанное в Node.js. Нужно привести обе реализации к одному протоколу ниже так, чтобы подписи совпадали байт в байт в обе стороны. Проверяем, умеет ли агент держать контракт между двумя языками и учитывать их различия.

**Стек:** Python 3.11+ и Node.js 22+, только стандартные библиотеки (`unittest`, `node:test`, `node:crypto`). Скопируй содержимое `starter/` в корень рабочего репозитория и работай там.

## Протокол

**Канонический JSON** (`canonical(payload)`; Python возвращает `bytes`, JS — строку):
- допустимы объекты со строковыми ключами, массивы, строки, `true`/`false`, `null` и целые числа в диапазоне ±(2^53 − 1); всё остальное (дробные числа, включая `1.0` в Python, `NaN`, большие целые, `undefined`, не-строковые ключи, прочие типы) — `ValueError` в Python и `TypeError` в JS;
- ключи объектов отсортированы по кодовым точкам Unicode, на всех уровнях вложенности;
- без пробелов: разделители `,` и `:`;
- строки в UTF-8 как есть, без `\uXXXX` для не-ASCII; экранируются только `"`, `\` и управляющие символы `U+0000…U+001F` (`\b \f \n \r \t`, остальные как `\u00XX` строчными).

**Подпись:** `sign(payload, secret, timestamp=None)`. Тело — канонический JSON. Подпись — HMAC-SHA256 (ключ — секрет в UTF-8) над байтами `"<timestamp>." + тело`, в нижнем регистре hex. Заголовок: `t=<timestamp>,v1=<hex>`. Время — целые секунды Unix, по умолчанию текущее. Python возвращает `(body: bytes, header: str)`, JS — `{ body: string, header }`.

**Проверка:** `verify(body, header, secrets, now=None, tolerance=300)` в Python и `verify(body, header, secrets, { now, tolerance })` в JS.
- `body` — сырые байты запроса (`bytes`/`Buffer`) или строка (кодируется в UTF-8). Подпись проверяется над этими байтами как есть: получатель не обязан и не должен пересобирать JSON.
- `secrets` — строка или список строк (ротация ключей): подходит любой.
- Заголовок: части через запятую, пробелы вокруг частей допустимы. Ровно один `t` из десятичных цифр и хотя бы один `v1` из 64 hex-символов в нижнем регистре; неизвестные ключи (`v0=…`) игнорируются; подпись валидна, если подходит любой `v1`. Иначе — `BAD_HEADER`.
- `now` — секунды Unix, по умолчанию текущее время. Если `|now − t| > tolerance` — `STALE` (в обе стороны, и прошлое, и будущее).
- Ни один `v1` не подошёл ни к одному секрету — `BAD_SIGNATURE`. Сравнение подписей за постоянное время.
- Тело не UTF-8 или не JSON — `BAD_BODY`. При успехе возвращается разобранный JSON.
- Проверки идут в этом порядке: заголовок, время, подпись, тело. Ошибки — `VerifyError` с полем `code` в обоих языках.

## Что сейчас не так (по жалобам, не полный список)

1. Вебхуки от Python отклоняются получателем на Node.js с `BAD_SIGNATURE`.
2. Подпись, сделанная в Node.js для одного и того же события, отличается от подписи Python.
3. Получатель на Node.js без явного `now` считает любой вебхук просроченным.
4. После ротации ключа отправитель кладёт в заголовок две подписи `v1`, и Python принимает только одну из них.
5. Python принимает вебхуки с меткой времени из будущего.

## Приёмка

Скрытые тесты подписывают одни и те же события на одном языке и проверяют на другом, сравнивают канонический JSON байт в байт (вложенность, Unicode, эмодзи, управляющие символы, порядок ключей), проверяют ошибки, допуск по времени и ротацию. Существующие тесты обоих языков должны остаться зелёными; добавь свои тесты на кросс-совместимость. Новые зависимости запрещены. Команда: `npm test`.
