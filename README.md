## Замеры

Задания 003–007 (простой набор) и 008–012 (сложный набор) — для регулярного замера движка: после каждого этапа доработки одни и те же ТЗ прогоняются заново и сравниваются три числа: доля решённых задач, $ на задачу и время на задачу. Задача считается решённой, если проходят скрытые приёмочные тесты; агент их не видит. Эталонные решения и скрытые тесты хранятся вне этого репозитория. Для `starter/`-заданий агент копирует стартовый код в корень своего рабочего репозитория.

## Компонент поля тегов (`src/tagInput.js`)

Поле ввода тегов без фреймворков: обычный DOM, клавиатура, доступность и очистка ресурсов.

### Установка

```bash
npm install   # единственная dev-зависимость — jsdom (для тестов)
npm test      # запуск тестов через node --test
```

Требуется Node.js с поддержкой ESM и встроенного тест-раннера (`node --test`).

### Подключение в HTML

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <title>Tag input</title>
  </head>
  <body>
    <div id="tags"></div>

    <script type="module">
      import { createTagInput } from './src/tagInput.js';

      const api = createTagInput(document.getElementById('tags'), {
        initial: ['js', 'dom'],
        maxTags: 5,
        onChange: (tags) => console.log('tags:', tags),
        removeLabel: (tag) => `Удалить ${tag}`,
      });

      // api.getTags() -> ['js', 'dom']
      // api.setTags(['css']) — заменить набор без вызова onChange
      // api.destroy() — снять обработчики и удалить разметку
      window.tagInput = api;
    </script>
  </body>
</html>
```

Компонент сам создаёт внутри контейнера разметку `ul.tags` и `input.tag-input`, поэтому в HTML достаточно пустого `<div id="tags">`.

### Опции

| Опция         | Тип                        | По умолчанию            | Описание                                                                 |
| ------------- | -------------------------- | ----------------------- | ------------------------------------------------------------------------ |
| `initial`     | `string[]`                 | `[]`                    | Начальный набор тегов. Валидируется как `setTags` (иначе `TypeError`).   |
| `maxTags`     | `number`                   | `10`                    | Максимум тегов; при достижении лимита поле ввода становится `disabled`.  |
| `onChange`    | `(tags: string[]) => void` | —                       | Вызывается после изменений пользователем; получает копию массива тегов.  |
| `removeLabel` | `(tag: string) => string`  | `` (tag) => `Remove ${tag}` `` | Текст `aria-label` для кнопки удаления тега.                       |

### API

`createTagInput(container, options)` возвращает объект:

- `getTags(): string[]` — копия текущего набора тегов в порядке добавления.
- `setTags(tags: string[]): void` — заменить набор. Бросает `TypeError`, если передан не массив, тег не проходит валидацию или тегов больше `maxTags`; при ошибке текущее состояние не меняется. `onChange` не вызывается.
- `destroy(): void` — снять все обработчики и удалить `ul.tags` и `input.tag-input` из контейнера. Идемпотентна: повторный вызов ничего не делает.

Дополнительно модуль экспортирует хелперы:

- `normalizeTag(v): string` — `String(v).trim().toLowerCase()`.
- `isValidTag(t): boolean` — проверка по `/^[a-z0-9\-а-яё]{1,30}$/`.

### Поведение

- `Enter` и `,` добавляют тег из поля ввода; пустое значение игнорируется.
- Ввод с запятыми (`a, b,c`) разбирается на теги, в поле остаётся последний незавершённый фрагмент.
- `Backspace` в пустом поле удаляет последний тег.
- `blur` добавляет набранный тег.
- Клик по кнопке `.tag-remove` удаляет тег и возвращает фокус в поле ввода.
- Недопустимый тег помечается `aria-invalid="true"`; повтор уже добавленного тега просто очищает поле.
- Теги нормализуются (trim + нижний регистр) и дедуплицируются.
