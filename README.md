## Задание 003 — ledger CLI

`ledger` — небольшой CLI на Python для отчётов по CSV-файлу с проводками,
запускаемый как `python -m ledger` из корня репозитория.

### Запуск

```
python -m ledger report FILE [--from YYYY-MM-DD] [--to YYYY-MM-DD] [--account PREFIX]
```

Точный пример вызова:

```
python -m ledger report ledger.csv --from 2024-01-01 --to 2024-12-31 --account assets
```

* `FILE` — путь к CSV-файлу с проводками (обязательный позиционный аргумент).
* `--from YYYY-MM-DD` — включать только проводки с этой даты (включительно).
* `--to YYYY-MM-DD` — включать только проводки по эту дату (включительно).
* `--account PREFIX` — включать только счёт `PREFIX` и его дочерние счета
  (`PREFIX:...`).

### Формат CSV

Первая строка — заголовок. Обязательные колонки: `date`, `account`,
`amount`, `currency`; колонка `memo` опциональна. Порядок колонок произволен,
кодировка — UTF-8 (BOM допускается). Полностью пустые строки пропускаются.

```csv
date,account,amount,currency,memo
2024-01-02,assets:cash,100.00,USD,initial deposit
2024-01-05,expenses:food,-12.50,USD,lunch
2024-02-01,assets:cash,-3.25,USD,coffee
```

* `date` — `YYYY-MM-DD`, календарно-корректная дата.
* `account` — непустые сегменты, разделённые `:`, без окружающих пробелов.
* `amount` — `-?\d+(\.\d{1,2})?` (знак и не более двух знаков после точки).
* `currency` — ровно три заглавные буквы (`[A-Z]{3}`).

### Вывод (JSON)

В stdout печатается один JSON-объект: список счетов с балансом (сумма по
паре «счёт + валюта», округлённая до 2 знаков) и общее число учтённых
проводок. Счета отсортированы по `(account, currency)`.

```json
{
  "accounts": [
    {"account": "assets:cash", "currency": "USD", "balance": "96.75"}
  ],
  "total_transactions": 3
}
```

### Коды выхода

* `0` — успех, JSON-отчёт записан в stdout.
* `1` — файл не удалось прочитать (нет файла, это каталог, нет прав, ошибка
  декодирования).
* `2` — неверное использование CLI/аргументы или некорректные данные CSV.

На любом пути ошибки ровно одно сообщение пишется в stderr, а stdout
остаётся пустым. Ошибки данных рендерятся как `line N: <reason>`.
