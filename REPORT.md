# Отчёт: ttlcache — исправление пяти репортов

Формат: изменено → проверено → блокеры → PR.

## Изменено

- **Репорт 1 (граница TTL):** `_expired` и `purge` теперь считают запись истёкшей при `clock() >= expires_at`, поэтому запись с `ttl=10` истекает ровно на 10-й секунде, а не на 11-й.
- **Репорт 2 (LRU в `get`):** при успешном попадании `get` вызывает `self._data.move_to_end(key)`, поэтому часто читаемые ключи не вытесняются первыми.
- **Репорт 3 (`set` по существующему ключу):** `set` для уже присутствующего ключа обновляет значение и `expires_at`, делает `move_to_end` и возвращается до логики вытеснения, поэтому повторная запись не выкидывает другие записи.
- **Репорт 4 (истёкшие записи в `__contains__`/`__len__`):** `__contains__` возвращает `False` для просроченной записи, а `__len__` считает только не просроченные записи, не трогая счётчики `hits`/`misses`.
- **Репорт 5 (неположительный `ttl`):** `set` бросает `ValueError('ttl must be > 0')` при `ttl <= 0` до любых мутаций `self._data` и счётчиков.

## Проверено

- `python -m unittest` из корня репозитория зелёный; прогон зафиксирован в `test_report.txt` через `run_tests.py`.
- Добавлены пять регрессионных тестов, по одному на репорт: `test_expires_at_exact_boundary`, `test_get_refreshes_lru_order`, `test_set_existing_key_updates_without_evicting`, `test_expired_entries_not_counted_and_do_not_touch_counters`, `test_set_rejects_non_positive_ttl`.
